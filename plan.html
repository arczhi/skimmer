RLCD 训练方案：面向真实阅读场景

目标不是跑分，而是让模型在真实任务（长文划重点、工单分派、动态问题决策）上表现可靠：判断准、概率可信、覆盖用户自定义的问题与候选项。

1. 现状与差距

模型底座 / 任务数训练方式公平套件 acc
v5（当前阅读器所用）1.7B / 24全参 + 集成蒸馏0.654
stage12B Qwen3.5 / 45LoRA r=320.642
decider-2b2B Qwen3.5 / 95全参 + 校准 RL0.700

两个明确结论：

  • LoRA 容量不足：更强底座 + 更多任务换成 LoRA 后，反而不如旧的全参模型（Biderman 2024：LoRA 学的扰动秩比全参低 10-100 倍）。
  • 对齐税：45 任务 SFT 后远距离未见任务（sciq / xstory / dolly）反而降了 1~10pt，需要防遗忘机制。

2. RLCD 实验已确认的成分

组件结论是否纳入
belief proper-score（合成概率律）有效：excess 0.0019 nats纳入 纳入（15% 数据）
真实歧义 belief（GoEmotions 3 标注者分布）有效：excess 0.030 / ECE 0.005纳入 纳入
listwise CE + label smoothing有效纳入 纳入
KD 蒸馏（强教师）有效（v5 的 NLL 1.451 为全场最佳）待定 有了多个强变体后再做
action RL（REINFORCE）零贡献（v3b 消融）不用 不用

关键判断：RLCD 的有效部分是 belief 校准，不是 RL。泛化差距要靠任务覆盖与容量解决。

3. Stage 2 训练方案

3.1 数据（45 → ~70 任务，偏向真实用途）

  • 摘要显著性（阅读器刚需）：CNN/DailyMail、multi_news，把摘要里的句子作为 gold，训练"哪些句子值得读/进入摘要"。
  • 工具 / API 选择：在已有 glaive / hermes / toolace 基础上补充真实 agent 任务。
  • 领域分类：法律（lex_glue 子集）、金融、医疗（已有 medmcqa / medqa）。
  • 保持 45 个现有任务，公平套件 8 任务严格不训练（OOD 门禁）。

3.2 训练配方

底座:  Qwen3.5-2B 文本塔（全参微调，8-bit Adam）
损失:  L = CE(listwise, ls=0.05)                  # 任务正确性
         + 1.0 · belief_proper_score(15% 数据)    # 概率校准
         + 0.1 · KL(决策分布 ‖ 基座决策分布)       # 防遗忘（对齐税）
上下文: max_state_tokens 256 → 1024（长文与阅读器场景）
步数:  5000，lr 1e-5，warmup 200 + cosine，grad_clip 1.0
显存:  权重 4G + 梯度 4G + 优化器 4G + 激活 ~5G + 参考模型 4G ≈ 21G ✓

4. 里程碑与成本

阶段内容时间
M1 数据新数据集探测 + 转换器 + 构建（含显著性）~0.5 天
M2 冒烟全参 + 长上下文显存/速度验证（30 步）~1 小时
M3 全量5000 步全参训练（含 KL 防遗忘）~5.5 小时
M4 评测全部套件 + 导出 MLX~1 小时

5. 风险与对策

  • 显存紧张（全参 2B + 1024 上下文）：batch 1 + 梯度检查点；必要时 512 上下文先行。
  • 对齐税加重（全参漂移更大）：KL 权重扫描 0.05 / 0.1 / 0.2，以公平套件为准。
  • 显著性数据噪声：用抽取式 oracle 构造标签 + 人工抽检 100 条。
  • 时间：pod 可能关机 → checkpoint 每 2000 步 + 看护脚本自动回传。

6. 长线（Stage 3+）

  • 任务扩到 95（对齐 decider 覆盖度），配比实验（任务族权重、难度归一化）。
  • 多模态 state encoder（图文候选打分，同一 scorer 架构）。
  • 多个强变体（全参 / 不同种子）→ 集成 → KD 融合成单模型。
